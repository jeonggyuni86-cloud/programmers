
# 도커란?

도커는 컨테이너를 만들고 실행하고 배포하는 도구다.

도커는 새로운 격리 기술을 만든 것이 아니다.
리눅스가 이미 가지고 있던 기능(`namespace`, `cgroup`)을 **쓰기 쉽게 감싸고**,
실행 환경을 **하나의 파일로 묶어 옮길 수 있게** 만든 것이다.

## 1. 도커가 제공하는 세 가지
- 이미지 : 실행 환경을 담은 패키지 - 배포의 단위
- 컨테이너 : 이미지를 실행한 상태 - 실행의 단위
- 레지스트리 : 이미지를 저장하고 주고받는 저장소 - 유통의 경로

- **도커 허브** : 도커사가 운영.

## 2. 이미지와 컨테이너

- **이미지는 읽기 전용이다.** 한번 만들어지면 내용이 바뀌지 않는다.
- **컨테이너는 그 이미지를 실행한 것이다.** 하나의 이미지로 컨테이를 몇 개든 만들 수 있고, 각 컨테이너는 서로 독립적으로 동작한다.

### 이미지에 들어 있는 것
- 애플리케이션 실행 파일
- 실행에 필요한 런타임
- 운영체제의 파일 시스템 일부(라이브러리와 기본 명령어들)
- 시작 방법 - 어떤 명령으로 실행할 것인지에 대한 정보

### 들어 있지 않은 것

**커널이다.** 커널은 이미지에 포함되지 않고 호스트의 것을 그대로 사용한다.

## 3. 이미지는 파일 시스템이다.

이미지는 디렉터리 트리 하나다. `/usr`, `/lib`, `/opt`, `/app` 같은 것들이 들어 있는 파일 묶음이다.

실행에 필요한 파일들이 디렉터리 구조로 담겨 있고, 컨테이너의 프로세스는 **이 트리를 최상위 경로로 보고** 동작한다.

## 4. 이미지는 계층으로 쌓인다.

이미지 기반이 되는 이미지 위에 변경된 내용을 층으로 얹어 만든다.
만드는 과정에서 발생한 **파일 시스템의 변경분이 계층 하나**가 된다.

```
FROM eclipse-temurin:25-jre     # 계층 1: 리눅스 파일 + JRE 전체  (/usr, /lib, /opt/java, /etc ...)
WORKDIR /app                    # 계층 2: /app 디렉터리 하나
COPY app.jar /app/app.jar       # 계층 3: /app/app.jar 파일 하나
```
